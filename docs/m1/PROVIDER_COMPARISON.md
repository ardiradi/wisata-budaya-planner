# M1 routing and map-provider comparison

Assessment date: **2026-10-23, Asia/Jakarta**. Evidence class: **DOC only**. M1 remains **OPEN / NO-GO for M2**. This document adds public-source research; it does not change the approved product, work ceilings, source rules or provider selection. No sign-in, key inspection/configuration, application API request, provider account creation, provisioning, deployment, external contact or paid work occurred. The existing 54-test results were not rerun or promoted to live evidence.

**Recommendation:** nominate **Geoapify for contractual clarification** because its public Routing API documentation expressly supports storing and redistributing results. Keep a **self-hosted OSM + Valhalla/OSRM + MapLibre design** as the durable-data alternative, subject to licensing and operations review. Neither is adopted. Google and Mapbox remain on hold for this product's permanent route-derived schedules/costs without additional permission. Hosted openrouteservice remains a candidate with incomplete current contractual evidence.

## 1. Decision being evaluated

The durable requirement is larger than retaining a polyline: origin/destination bindings, duration/distance, buffers, walking totals, shifted visit times, estimated transport costs, totals/contingency, validation results, immutable history, exports and backup copies can all depend on routing inputs. Deleting the raw response does not remove those dependencies. A tile-storage allowance does not settle routing-output rights, and a renderer's software license does not license map data.

`Positive DOC` below means an affirmative public statement was found for the specified use, subject to its conditions. `Hold` means positive permission or an applicable exception has not been established for the exact purpose. `Conditional` means a plausible licensed design still needs an accountable rights/privacy decision and evidence. These labels are engineering assessments, not legal advice, accepted terms, provider assurances or human approval. Confidence concerns the cited evidence, not actual Palembang route quality.

Google's [mode reference](https://developers.google.com/maps/documentation/routes/reference/rest/v2/RouteTravelMode), Mapbox's [Directions “Routing profiles”](https://docs.mapbox.com/api/navigation/directions/), and Geoapify's [Routing API](https://www.geoapify.com/routing-api/) document modes rather than local operational suitability. Successful driving routing never establishes ride availability, fares, lawful pickup, parking or boarding access. A walking path never certifies continuous step-free access. All alternatives retain the existing M1 directed entrance/mode/barrier review gate.

OSRM's [API, “General options”, “Route service” and “Table service”](https://project-osrm.org/docs/v5.24.0/api/) describes profiles built during extraction and duration/distance outputs; car/foot graphs need the appropriate prepared profile. Its optional geometric fallback is **not** an approved feasibility fallback. Valhalla's [route API “Costing models”](https://valhalla.github.io/valhalla/api/route/api-reference/) offers auto/pedestrian and taxi road-access costing; its taxi option does not provide a bookable vehicle or fare. These are documentation checks, not tests of an installed engine or a selected release.

## 3. Clause-level evidence and remaining permissions

### G — Google

The current non-EEA [general terms §§3.2.3 and 4.4](https://cloud.google.com/maps-platform/terms) retain restrictions on caching/content derivation and model improvement through training/testing/validation/fine-tuning. That wording is not an express blanket ban on every runtime inference. §4.4 permits provider collection/use/retention of request data and uses controller-controller terms; do not describe Maps universally as a zero-retention processor.

[Service-specific B.19](https://cloud.google.com/maps-platform/terms/maps-service-terms) permits Routes use without a map, prohibits use with a non-Google map, and gives a 30-day lat/lng exception. It does not name duration/distance derivatives. B.10's Maps Grounding Lite exception is product-specific, not a generic Routes-to-LLM permission. [Routes policies](https://developers.google.com/maps/documentation/routes/policies), “Exceptions from caching restrictions” and “Google Maps attribution requirements”, address IDs/display attribution, not permanent itinerary derivatives.

**Assessment G1:** direct permitted display is distinguishable from our proposed calculations; exact transient and permanent derivative purposes remain **Hold**. The customer's billing jurisdiction/agreement, raw/derived retention, backups and downstream-use permission need review. Confidence **high** in the clauses; no confidence claim about permission not found or live coverage.

### M — Mapbox

The [Product Terms portal](https://www.mapbox.com/legal/product-terms) links an **October 20, 2026 PDF**, actually read through an in-memory HTTPS download/text extraction after the web PDF parser failed. In that PDF: §1.5(ii) restricts using offerings to **train, operate or improve** AI/ML; §§1.5–1.6 restrict derived works/extraction; §1.9 supplies default storage restrictions; §2.10.1 forbids exporting/downloading/caching/storing Navigation API results. §2.8.1's limited on-device mapping cache is separate. Definitions §§3.32/3.43/3.50 distinguish map content, Mapping APIs and Navigation APIs. Older search results describing a 30-day navigation cache are not the current portal-linked evidence.

**Assessment M1:** do not infer generic runtime-AI permission here; its language is broader than Google's model-improvement example. Permanent navigation results and route-derived schedules/costs/backups are **Hold**, needing an applicable written exception and interpretation. Commercial eligibility and any additional license must fit the actual application category/order. Confidence **high** in the read PDF; actual agreement applicability remains unproved. [Portal-linked Product Terms PDF](<https://cdn.prod.website-files.com/609ed46055e27a02ffc0749b/6ad79764a359d21b46049ea4_Mapbox%20Product%20Terms%20(October%2020%2C%202026).pdf>).

Mapbox's [attribution guide](https://docs.mapbox.com/help/dive-deeper/attribution/), “When you're not using a map” and “When you're using a non-Mapbox map”, describes attribution for some off-map/other-map uses. That is display guidance, not an override of M1's purpose/storage restrictions. Preserve attribution and determine which exact service may be displayed with the chosen map.

### O — Hosted openrouteservice

The [official main site](https://openrouteservice.org/) currently announces website unavailability and points to the account portal/backend documentation. The old API terms/plans URLs returned 404; staging returned 403. The linked [current API terms page](https://account.heigit.org/info/tos) exposed no readable text, and unauthenticated direct retrieval timed out. The forum's own generic TOS is not substituted for the API agreement.

An [operator-hosted forum reply dated October 12, 2026](https://ask.openrouteservice.org/t/free-plan-in-an-app-with-a-paid-tier-license-cc-by-sa-4-0-personal-data-and-attribution-questions/8079), by `jschnell`, states Standard permits commercial use and results use CC BY-SA 4.0; it directs users back to current terms and declines detailed licensing advice. This is useful **medium-confidence public guidance**, not an executed agreement or this project's human approval. Do not label all free ORS access noncommercial or generalize restrictions from a different plan.

**Assessment O1:** confirm current Standard/commercial quotas, output license scope, attribution, personal-data restriction, derivatives and termination/retention from readable applicable terms. A CC BY-SA output grant, if confirmed, is materially different from proprietary no-storage terms, but share-alike implications need review. Hosted output/storage/AI/backups remain **Conditional/Hold** until then. [Backend FAQ](https://giscience.github.io/openrouteservice/frequently-asked-questions), “I want to use the HeiGIT API in my application”, requires protecting a person's API key server-side; it is not permission to create/use a key now.

### A — Geoapify hosted

Geoapify's [Routing API, “Easy to use and permissive”](https://www.geoapify.com/routing-api/) affirmatively allows storing/redistributing routing results. Its [Products and Services, “Open data and permissive conditions”](https://www.geoapify.com/products-and-services/) permits cache/storage/redistribution of service results. Its [Map Tiles, “OpenStreetMap-based Tiles”](https://www.geoapify.com/map-tiles/) separately allows tile cache/storage/redistribution. These are **Positive DOC** statements; none should be silently relabeled legal approval for every downstream purpose.

The [Terms, “Attribution” and “Plans and usage limits”](https://www.geoapify.com/terms-and-conditions/) require OSM attribution and Geoapify attribution on Free, with possible additional API attribution. The [Pricing FAQ](https://www.geoapify.com/pricing/) explicitly permits commercial production on Free within limits, but describes quotas as soft. Free eligibility is not free entitlement, an enforced monthly spend cap or authorization for an API call.

**Assessment A1:** the strongest hosted candidate found for durable results, rather than merely absent prohibitions. App-specific cost/schedule derivatives, immutable history, exact underlying-data/share-alike scope, backups after termination and AI uses still need an approved policy/contract interpretation. Confidence **high** in the positive published statements, **pending** for those exact purposes. Nominate for clarification only; no outreach is authorized or performed.

## 5. Self-hosted data licensing is separate from software licensing

OSRM's [LICENSE.TXT](https://github.com/Project-OSRM/osrm-backend/blob/master/LICENSE.TXT) provides permissive software redistribution conditions; Valhalla's [COPYING](https://github.com/valhalla/valhalla/blob/master/COPYING) is MIT. MapLibre's [LICENSE.txt](https://github.com/maplibre/maplibre-gl-js/blob/main/LICENSE.txt) contains its BSD-style notice and bundled notices. These licenses concern code; they do not license OSM, third-party traffic feeds, tiles, fonts, styles or historical/venue facts. Audit dependencies and dataset sources separately.

[OSM's copyright page](https://www.openstreetmap.org/copyright) identifies ODbL and attribution duties. [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), §§1, 3.1 and 4.3–4.6, positively grants commercial use and temporary/permanent reproduction subject to conditions. It distinguishes a database/Derivative Database from a Produced Work and limits/defines share-alike triggers. A separately licensed app is not automatically open-sourced by using OSM; nor is a systematically accumulated route/road database automatically an unrestricted Produced Work. Classify the actual graph, corrections, accumulated route results and schedule representation before use; public use can matter without a database download. Confidence **high** in license text, **pending** in project-specific classification.

The OSMF [Produced Work guideline, “The Guideline”](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Produced_Work_-_Guideline) considers extractability; a raster illustration is different from reusable structured road data. The [Horizontal Map Layers guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Horizontal_Map_Layers_-_Guideline) discusses independent versus interacting layers. Merely using different SQL tables is not proof that a proprietary dataset stays independent. The [Substantial guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Substantial_-_Guideline) warns against treating repeated small extraction as unrelated one-off use. These endorsed guidance pages aid interpretation, not a project legal sign-off.

For an ORS output actually covered by CC BY-SA 4.0, the [license §§2–4](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en) permits reproduction/adaptation subject to attribution, share-alike where applicable and database-right conditions. Determine which artifact is adapted and shared; do not claim that one scalar forces all app code to be licensed alike, or that it eliminates every condition. The current ORS API agreement and underlying OSM duties remain separate prerequisites.

The OSM Foundation's [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) has best-effort availability, attribution/caching requirements and prohibitions on bulk prefetch. Its community tile server is not an implicitly approved production backend for a self-hosted router. Plan own or separately licensed tile service and account for its requests/storage/egress. A map can also remain absent while the accessible itinerary list is used; this does not remove routing-evidence requirements.
